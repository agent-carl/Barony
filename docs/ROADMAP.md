> Детальный план работ. Статусы: ☐ не начато · ◐ в работе · ☑ готово.
> Оценки в «сессиях» — один сфокусированный заход разработки (0.5–2 дня работы).

## Этап 1 — Вертикальный срез (MVP)

Цель: 30 минут геймплея, где видны все четыре столпа
(свет/тьма, кооп 1–4, билды/крафт, намёк на сюжет).

### 1.1 Соло-компаньон *(разведка готова — кирпичи найдены)*
- ☐ **Автоспавн при старте одиночной игры**: хук в начале новой игры —
  если `multiplayer == SINGLE`, без сплитскрина, у игрока 0 нет
  последователей → `summonMonster(HUMAN)` у спавна + `forceFollower()`.
  Переносы между уровнями и сетевая синхронизация уже в движке. *(1 сессия)*
- ☐ Личность компаньона: имя, класс, стартовое снаряжение, реплики-«лай»
  (barks) при событиях. *(1–2)*
- ☐ Баланс соло: скалирование сложности при 1 игроке + компаньоне,
  запрет смерти компаньона ломать прохождение (воскрешение у
  чекпойнта или замена). *(1–2)*
- ☐ UX приказов: пройтись по `FollowerMenu` — читаемость, геймпад,
  подсказки для нового игрока. *(1)*

### 1.2 Механика «Свет против тьмы» (ядро хоррора)
- ☐ **Дизайн-спека механики** (до кода!): что даёт свет, что забирает
  тьма, какие источники, какая цена. Черновик: в темноте растёт шкала
  «страха/угрозы» → спавны усиливаются, у света — безопасность и
  восстановление; источники света — ресурс (факелы гаснут, топливо
  крафтится). *(1 сессия, документ)*
- ☐ Ревизия `light.cpp`: у каждой клетки уже есть уровень освещённости —
  вытащить API «насколько освещён игрок». *(1)*
- ☐ Шкала угрозы + эффекты тьмы (спавны, шёпоты, дебаффы). *(2–3)*
- ☐ Свет как ресурс: расход факелов/ламп, крафт топлива. *(1–2)*
- ☐ Визуал: виньетка/зерно в темноте, пульс шкалы страха. Движок уже
  умеет HDR — использовать. *(1–2)*

### 1.3 Крафт и билды (расширение существующего)
- ☐ Инвентаризация текущей системы (алхимия, тинкеринг) — что оставляем,
  что переименовываем под сеттинг. *(1, документ)*
- ☐ +10–15 своих рецептов, завязанных на свет/тьму (топливо, обереги,
  световые ловушки). *(2)*
- ☐ Каркас «билдов»: 3 стартовых архетипа (боец/оккультист/инженер) на
  базе классов Barony, с уникальными стартовыми рецептами. *(1–2)*

### 1.4 Сюжетный каркас (минимум для среза)
- ☐ **Синопсис сюжета**: завязка, 3 акта, финал — 1–2 страницы. Решение:
  линейные акты или хаб. *(документ, решение владельца по сеттингу!)*
- ☐ Система сюжетных триггеров: движок умеет скриптованные карты
  (редактор + `mod_tools`) — проверить, хватает ли для «двигаться по
  сюжету»: диалог → задача → переход. *(1 разведка + 2 имплементация)*
- ☐ Пролог-уровень: скриптованная стартовая карта, знакомит с компаньоном
  и механикой света. Собрать в редакторе Barony. *(2–3)*

### 1.5 Уровни среза
- ☐ Биом №1 «вчерне» (на ассетах Barony как плейсхолдерах): 3–5 уровней,
  свои тайлсеты позже. *(2)*
- ☐ 5–6 типов врагов из пула Barony, перебалансированных под тьму
  (реассет — этап 3). *(1–2)*

**Выход из этапа 1:** новая игра → пролог → 3–5 уровней с механикой
света/тьмы, компаньоном, крафтом — соло и в коопе. ~15–25 сессий.

## Этап 3 — Замена ассетов (юридический гейт релиза)

> **Блокер релиза №1.** Ни один проприетарный файл Barony не должен
> попасть в наш дистрибутив. Игра обязана запускаться и проходиться
> на 100% своих данных.

- ☐ **Инвентаризация ассетов**: скрипт-аудит того, что игра грузит
  (models.txt, images/, sound/, music/, maps/, lang/, items/) →
  чеклист замены с приоритетами. *(1 сессия, дальше — трекер)*
- ☐ **Арт-директория**: стиль-гайд (палитра, силуэты, референсы) —
  до заказа/создания ассетов. *(1–2 + решение владельца)*
- ☐ Источник арта — решение: свой художник / аутсорс / покупные паки /
  генеративные + ручная доводка / намеренный минимализм.
  Влияет на бюджет и сроки сильнее всего в проекте.
- ☐ 3D-модели: формат Barony — воксельные `.vox`-подобные модели
  (уточнить пайплайн при инвентаризации). Монстры, оружие, предметы,
  тайлы стен/пола, декор. *(самый большой объём проекта)*
- ☐ Спрайты/UI: инвентарь, иконки предметов, HUD, меню, шрифты
  (лицензии шрифтов проверить отдельно!). 
- ☐ Звук: SFX (шаги, бой, UI, амбиент) + музыка. Источники: заказ /
  стоки с лицензией / свои. Хоррор живёт звуком — не экономить.
- ☐ Тексты: все строки `lang/` — свои (сюжет и так наш; вычистить
  остатки текстов Barony).
- ☐ Карты: все `.lmp`-уровни пересобраны в нашем редакторе.
- ☐ **Финальная проверка чистоты**: билд на машине без Barony,
  автоматический дифф-аудит против файлов Barony. *(1)*

**Выход из этапа 3:** полное прохождение на чистой машине без Barony.
Сроки зависят от источника арта: реалистично 2–6 месяцев календарных.

## Критический путь и риски

**Критический путь:** арт-ассеты (этап 3). Всё остальное — управляемые
кодовые задачи в готовом движке. Решение об источнике арта нужно
принять уже на этапе 1, иначе этап 3 станет стеной.

| Риск | Вероятность | Митигация |
|---|---|---|
| Арт затянется/подорожает | Высокая | Минималистичный стиль как план Б; ранняя инвентаризация; плейсхолдеры до этапа 3 |
| «Ещё один кооп-хоррор» — не заметят | Средняя | Крючок: компаньон + свет-как-ресурс + билды; демо и стримеры до релиза |
| Легаси-код укусит (глобалы, C-стиль) | Средняя | Не рефакторить ради рефакторинга; менять точечно; CI ловит регрессии |
| Сетевой код под нашими фичами | Средняя | Каждую фичу сразу тестировать в коопе, не в конце |
| FMOD-лицензия при росте выручки | Низкая | Порог Indie-лицензии высокий; при успехе — оплатить или портировать |
| Выгорание соло-разработки | Средняя | Вертикальный срез раньше — играбельный результат мотивирует; резать скоуп, не качество |
